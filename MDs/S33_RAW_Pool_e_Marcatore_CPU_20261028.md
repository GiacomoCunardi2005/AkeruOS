# S33 V1.1 — pool e marcatore RAW nella stessa prova CPU

28 ottobre 2026. Il simulatore GNU ARC700 con modello DSP sperimentale esegue il produttore di stato, l'inizializzazione del pool interno e, su chiamata diretta del banco, il marcatore originale `0x28D5BC`. **NON_INSTALLARE**. Regione, selettore, riserve, descrittori, code e servizi sono sintetici; l'ordine è imposto dal banco.

Il caso prepara stato sintetico `0x0A`, selettore pool 0 e pool inizialmente inattivo. Il pool originale produce due indirizzi dati separati da **13.263.872 byte**. Il banco inizializza i 32 byte bersaglio con bit basso opposto alla tabella originale, poi invoca il marcatore sul primo indirizzo con `r16=0`, dimensioni 4208×3152 e selettore 2. Il confronto completo dell'area mappata dal primo indirizzo fino oltre l'ultimo bersaglio rileva esattamente **32 byte modificati**: uno 256 byte prima del secondo indirizzo e 31 tra 8.160 e 260.640 byte dopo. Il marcatore ritorna 0 e lo stack della chiamata è conservato.

Questo integra in un'unica esecuzione la disposizione sintetica e la scrittura dei bit precedentemente verificate separatamente. Non stabilisce che il secondo nodo sia attivo, che gli indirizzi o la capacità esistano in RAM fisica, né che quel ramo venga eseguito durante uno scatto reale. L'input è stato scelto per provocare tutte le 32 modifiche; altri dati possono richiederne meno. Il banco chiama direttamente il marcatore senza eseguire flag/menu o acquisizione; non legge un'immagine e non verifica file o JPEG. La richiesta 2N del writer è un risultato separato, non eseguito qui.
